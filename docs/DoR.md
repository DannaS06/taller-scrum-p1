# Definition of Ready (DoR)

La Definition of Ready establece los criterios que debe cumplir una historia de usuario antes de ser seleccionada para desarrollo.

Una historia se considera Ready cuando cumple con lo siguiente:

- La historia está claramente definida en formato:
  
  Como [rol] quiero [funcionalidad] para [beneficio]

- Tiene criterios de aceptación definidos en formato Gherkin:

  Dado / Cuando / Entonces

- Tiene valor de negocio identificado

- Tiene prototipo o diseño en Figma enlazado

- Tiene diagrama relacionado en PlantUML

- Las dependencias están identificadas

- Puede ser estimada por el equipo

- Tiene definido su Issue en GitHub

- Tiene creada su rama feature correspondiente

## Objetivo

Asegurar que el equipo comprenda completamente la historia antes de iniciar su desarrollo.
